# Header-only metadata reads with attached property blocks (1.3 regression fix)

## Why

EigenFrame desktop field report: WBPP 3.1 / PixInsight 1.9.5 masters failed to catalog with "could
not be read as a valid XISF image". These masters store `PixInsight:ProcessingHistory` as an
lz4hc-compressed String in an attached block near EOF. The desktop calls `ReadMetadataFromStream`
over a MemoryStream holding only 16 + header-length bytes. Since 1.3
(`20260919.rev1-implementation-contract.md` item 6, the eager block-backed property read), the
metadata path seeked past the end of that stream and threw `EndOfStreamException`. 1.1.3 and 1.2.9
returned `XisfStringProperty(id, "")` for such properties.

## What changed

- `Models.cs`: adds `XisfProperty.UnresolvedBlock` (init-only, type `AttachedDataBlock?`). Reusing the existing block record, instead of a new one, keeps the checksum and byte order that a later resolve would need, and the public surface stays additive. `XisfStringProperty` stays sealed because the placeholder is the plain type with the mark set. A `with` expression carries the mark, and the doc comment says to clear it with `UnresolvedBlock = null`.
- `Interfaces.cs`: the internal `XisfBlockReader` delegate now returns `ReadOnlyMemory<byte>?`. A null return means the block is not available from the source.
- `Storage.cs`: the monolithic `ReadMetadataAsync` reader returns null for an attached block when the stream is non-seekable or `position + size > Length`. `ReadAsync` and the distributed strategy are untouched.
- `XmlSerializer.cs`: `ReadBlockValue`/`ReadStringValue` return the unavailable `AttachedDataBlock`. String, vector and matrix properties get an empty placeholder with the mark set, applied only when non-null so resolved properties are not cloned; a matrix keeps its declared rows and columns. `SerializeProperty` throws `InvalidOperationException` naming the Id, with the clearing hint. That one check covers global, image and distributed-header writes.
- `Tests/HeaderOnlyMetadataTests.cs`: a synthesized WBPP-shaped master (an image, an inline `PCL:Signature:Integration`, an attached lz4hc history, an attached F64Vector, an attached lz4hc+sh F64Matrix, and a FITS keyword). Covers:
  - header-only sync and async reads
  - full-stream resolve and `ReadAsync`
  - the exact-end and one-byte-short boundary
  - a non-seekable stream
  - a global attached property with a bogus checksum, which stays unresolved and unvalidated
  - the write guard, asserted independent of property order
- `CHANGELOG.md`: a `### Fixed` block under `## 1.3`. `VersionPrefix` is unchanged.

Suite: 284 before, 294 after, all green. `dotnet build -c Release` reports 0 warnings.

## Deviations

None from the agreed contract. Notes:
- After review, `UnresolvedBlock` uses `AttachedDataBlock` instead of the first-pass `XisfUnresolvedBlock` record, which never shipped.
- The write guard lives in the serializer, not in unit validation. Validation does not visit global properties, and the serializer is the one point every write path passes through.

## Out of scope (1.4 follow-up)

Pre-existing: an `XisfRawProperty` (unrecognized type) with `location="attachment:..."` is re-emitted verbatim on write (`XmlSerializer.cs`, `DeserializeProperty` raw fallback and the `SerializeProperty` raw branch). The output then carries an attachment reference to a block the writer never copies.
