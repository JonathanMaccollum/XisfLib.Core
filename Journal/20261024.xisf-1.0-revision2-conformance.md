# XISF 1.0 Revision 2 conformance (1.4)

Spec: `../XisfLib/docs/XisfSpecification 1.0 Revision 2.md`, §2.1, §10.6, §10.6.1, and the decoder conformance list. Process template: `20260919.rev1-implementation-contract.md` and `20260919.rev1-red-green-ledger.md`. This builds on `20261024.header-only-metadata-attached-property.md` (1.3.11), which is unchanged.

## Binding decisions

Owner decisions after a Fable-vetted game plan; the planning documents are not kept.

- Reader:
  - A subblock with `ci == ui` is uncompressed. A block without `subblocks` is one implicit subblock.
  - `ci < ui` and `ci > ui` subblocks are always decompressed and must produce exactly `ui` bytes.
  - The sums must match exactly: `ci` sums to the stored size and `ui` to the declared size.
  - Every malformed block throws `InvalidDataException`. There is no lenient option.
  - The checksum is verified over the stored bytes before anything is decompressed. Unshuffling happens once, after concatenation.
- Legacy probe:
  - It runs only on `ci == ui`, and only behind `XisfReaderOptions.TryDecompressEqualLengthSubblocks`, which defaults to true.
  - It tries to decompress first and falls back to a raw copy.
  - It succeeds only when the codec reports no error and produces exactly `ui` bytes, and, where the codec can tell, has consumed all of its input.
  - It decodes into the destination slice without throwing. A raw copy overwrites a failed probe.
- Malformed declarations: a malformed `subblocks` attribute, and an unparsable `+sh` item size, go through `UnsupportedDeclaration`. The header still parses, and the block fails when it is materialized.
- Writer:
  - A subblock that does not shrink is stored raw (`ci == ui`, shuffled bytes).
  - When nothing shrinks, on either path, it drops `compression` and returns the original unshuffled data.
  - There is no merge or compatibility mode.
- Blocks too large for one managed array throw `NotSupportedException` before allocation.
- `VersionPrefix` goes 1.3 → 1.4.

## What changed

- `DataBlockProcessor.cs`:
  - `DecompressBlock` and `ReconcileSubblocks` implement the reader rules. `CompressBlock` implements the writer rules.
  - `RejectUnsupported` adds the size guard. It covers a compressed block's declared size and an attached block's stored size.
  - The dead `WriteDataBlockAsync` is deleted, along with the `WriteAttachedBlockAsync`/`WriteExternalBlockAsync` helpers that only it used.
- `Compression.cs`, `Interfaces.cs`:
  - The internal `ICompressionProvider.TryDecompress(compressed, codec, destination)` replaces `Decompress`.
  - zlib must return 0 on one more `Read`, which rejects over-long output. A present Adler-32 trailer is verified, but a missing trailer or trailing bytes are not detected.
  - LZ4 must return `Decode == destination.Length`. zstd must return `Unwrap == destination.Length`.
  - Failures become `false`: `InvalidDataException`, the zlib `IOException`, and `ZstdException`.
  - `WriteDataBlockAsync` is removed from `IDataBlockProcessor`.
- `XmlSerializer.cs`: `ParseSubblocks` returns `(list, malformed)`. `ParseCompression` routes both malformed cases to the carrier.
- `Models.cs`: the new reader option, the only public API change. The `UnsupportedDeclaration` doc is updated.
- Section renumbering: all §10.6.x references in source and tests move to Rev 2 numbering. The two references that were already wrong now say §10.6. The Rev 1 journals are left as written.
- Tests:
  - new `Tests/CodecKit.cs` (independent codecs, `Noise`/`Ramp`, the equal-length legacy stream builder)
  - new `Tests/UncompressedSubblockTests.cs`
  - new `Tests/BlockIntegrityTests.cs`
  - new `Tests/RealFileFixtureTests.cs`
  - payload-only fixture edits in `Tests/CompressionTests.cs` and `Tests/ChecksumTests.cs`
- `XisfLib.Core.csproj`: version 1.4. `README.md` and `CHANGELOG.md` add the `## 1.4` section, with the runtime tightenings first.

## Red / green

- Before: 294 tests, all passing. After: 482 tests. 480 pass, and 2 are skipped, the real-file tests when `XISF_FIXTURES_DIR` is unset.
- Red was measured on a scratch copy of the HEAD source with only the option stub added: 127 of the first 169 new cases failed. Each was a new Rev 2 behaviour. The remaining cases were green as expected at HEAD:
  - `ci > ui` decompression
  - probe-on legacy reads
  - per-codec short output
  - checksum before probe
  - the compressible split
- Review fixes:
  - The 16 zlib FDICT-header cases fail when the catch is narrowed back to `InvalidDataException`.
  - New cases also cover the unparsable `+sh` item size, a third component on a non-shuffling codec, and an oversized attached block.
- Real files: the tests ran with `XISF_FIXTURES_DIR=W:\Astrophotography`, reading the originals read-only with nothing copied. All 5 passed.
- `dotnet build -c Release` reports 0 warnings for both projects.

## Deviations

- The contract and the red/green ledger are folded into this one entry. Production code was written before red was measured, so red comes from the HEAD scratch copy.
- `ICompressionProvider.Decompress` was removed, not kept, because it had no caller left.
- The size guard uses `Array.MaxLength`, the real allocation limit, not `int.MaxValue`.
- The two-subblock PixInsight fixture (`Eye of Smaug ... Aligned.BlurXCorrectOnly.xisf`) declares 2,293,482,960 uncompressed bytes. PixInsight splits only past the codec limit, so every such file is that large and none can be fully read into one array. Its test checks that the header-only read succeeds and that the 2 subblock sums reconcile. It expects `ReadAsync` to throw `NotSupportedException`.
- The review named `ZLibException` as the type to catch, but it is internal in .NET 8 and cannot be named. The catch takes its public base, `IOException`, which is safe because the source is an in-memory stream.
- Fixture edits went beyond the 14 enumerated cases. All changed payloads only:
  - Two checksum tests declared `zlib:16` over 16 stored bytes, which is now a raw subblock; they now declare `zlib:32`.
  - `Write_SingleSubblock_EmitsNoSubblocksAttribute` now uses a compressible payload.
  - The two round-trip theories now write, then read, so they can assert that `compression` was emitted.
- An empty or whitespace `subblocks` attribute is now treated as malformed.
- The zstd equal-length fixture is a flushed streaming frame in which the zero prefix forms its own RLE block. One-shot zstd jumps past equality.

## Still open

- Pre-existing: an attached `XisfRawProperty` is re-emitted verbatim on write. The output then references a block the writer never copies (see the 1.3.11 entry).
- A `+sh` codec with no item size at all still reads unshuffled. This pass covered only the unparsable case.
- PixInsight-saved fixtures will settle whether PCL raw subblocks under `+sh` hold shuffled bytes. The manual PixInsight checkpoint is also still to do, as are publish, the Worker unpin and the workspace CLAUDE.md fix.
