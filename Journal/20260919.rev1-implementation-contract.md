# Rev 1 implementation contract (binding for all TDD waves)

Shared contract for the 1.3 conformance work. Companion to
`20260919.xisf-1.0-revision1-conformance-assessment.md` (the gap list) — read that first. Spec
source: `S:\Claude\Astro\XisfLib\docs\XisfSpecification 1.0 Revision 1.md` (read-only; prose,
grammars, and identifier tables are authoritative there; its equations are stripped but none are
needed for this scope). Waves may read that spec file and this repo; **all writes stay inside
`S:\Claude\Astro\XisfLib.Core`; no git operations of any kind.**

## Scope (in)

1. **Scalar property widths** — read+write for Int8/UInt8/Int16/UInt16/Int64/UInt64 via the existing
   `XisfScalarProperty<T>` (sbyte/byte/short/ushort/long/ulong), joining Int32/UInt32/Float32/Float64.
2. **Boolean** — parse accepts `true`/`false`/`1`/`0`; emit stays `true`/`false`.
3. **Non-finite floats** — parse all spec forms (`NaN`, `+Inf`, `-Inf`, `nan`, `-nan`, `inf`, `-inf`)
   for Float32/Float64 scalars and vector/matrix elements where text-serialized; emit canonical
   `NaN`/`+Inf`/`-Inf`. Finite values keep G9/G17 invariant.
4. **byteOrder** — parse the attribute on any block-carrying element (Image, Property); default
   little. Wire `DataBlockProcessor.ConvertByteOrder` into the read path (order: checksum-verify →
   decompress → byte-order-convert → unshuffle is WRONG — correct order per spec: verify → decompress
   → unshuffle → byte-order applies to the *uncompressed, unshuffled* logical data; shuffling operates
   on bytes and is order-agnostic, but convert AFTER unshuffle). Emit `byteOrder="big"` never (we
   always write LE); never emit the attribute for 8-bit images, String, I8/UInt8 blocks.
5. **Inline + embedded block read** — `location="inline:base64|hex"` takes its data from the
   element's character content; `location="embedded"` takes it from the child `<Data>` element, whose
   own `encoding` and (when compressed) `compression` attributes govern. Zero-length inline block =
   empty vector/matrix (legal, the only zero-length block). Writer: image pixel data stays
   attachment-only (spec forbids inline on Image); property block values are written `inline:base64`.
6. **Vector/Matrix properties** — read+write for all of: I8/UI8(ByteArray)/I16/UI16/I32/UI32/I64/UI64,
   F32/F64 Vector and Matrix forms, using the spec's exact `type` identifiers (take the table from the
   spec §11.1.8/11.1.9 — do not guess names). `length` attr for vectors, `rows`+`columns` for
   matrices; value lives in a data block (read: any location incl. attachment; write: inline:base64,
   uncompressed by default). Row-major matrices. Empty vector/matrix round-trips.
7. **Preservation (opaque pass-through)** — new API surface:
   - `XisfHeader.UnknownElements : IReadOnlyList<XElement>` — any root child element not recognized
     (extension elements, unsupported core elements incl. ICCProfile/RGBWorkingSpace/DisplayFunction/
     Thumbnail) is captured verbatim and re-emitted on write, replacing today's silent drop.
   - `XisfImage.UnknownElements : IReadOnlyList<XElement>` — same for Image children.
   - A `<Property>` whose `type` is unrecognized becomes `XisfRawProperty(Id, XElement)` (new record,
     implements the property interface), re-emitted verbatim — replacing the silent misparse-as-String.
   - AstrometricSolution carriage needs NO special code: its types are F64Vector/F64Matrix/I32Vector/
     String/Int32/Float64/TimePoint (item 6 covers them), and anything unrecognized rides item 7.
8. **XML namespace** — writer emits `xmlns="http://www.pixinsight.com/xisf"` on the root and all core
   elements in that namespace (plus existing xsi:schemaLocation). Reader keeps accepting BOTH
   namespaced and bare names (legacy v1.2 output and any old third-party files must read forever).
9. **Checksums on write** — honor `XisfWriterOptions.CalculateChecksums`/`ChecksumAlgorithm` in the
   monolithic writer: digest computed over the stored (post-compression) bytes; attribute
   `algorithm:lowercase-hex` with hyphenated names (`sha-1` etc.). Requires computing block bytes
   before header emission (restructure the write ordering as needed; records are immutable — build
   final blocks first). Default remains what `XisfWriterOptions` defaults say today (do not change
   defaults).
10. **Checksum/codec failure policy** — declared-but-uncomputable checksum algorithm (sha3-*) or
    unknown codec: header parse succeeds; materializing THAT block throws the new typed
    `XisfUnsupportedObjectException`; other blocks stay readable. Checksum mismatch: still
    `InvalidDataException`, and decompression must provably not be attempted.
11. **Compression subblocks** — parse+emit the `subblocks="c1,u1:c2,u2:..."` attribute
    (`XisfCompression.Subblocks` already models it); read path: decompress each subblock
    independently, concatenate, THEN unshuffle (shuffle was applied to the whole block before
    splitting). Write path: single subblock remains the default; multi-subblock write only via
    explicit `Subblocks` on the compression record.
12. **Metadata** — serialize+deserialize ALL modeled `XisfMetadata` fields (today only 4 of 19), plus
    the four new Rev-1 properties: `XISF:BlockAlignmentSize` (UInt16), `XISF:ChecksumAlgorithms`
    (String, comma-sep), `XISF:MaxInlineBlockSize` (UInt16), `XISF:OutputHints` (String). Mind the
    spec's newline-separated vs comma-separated list split (assessment §E notes which).
13. **Validation** — add Image `id` uniqueness (new Rev-1 MUST); add error when a `+sh` codec has no
    `ItemSize`.
14. **Shuffle tail rule** — verify/fix `ApplyByteShuffle`/`RemoveByteShuffle`: trailing
    `size % itemSize` bytes stay unshuffled, stored after the shuffled run.
15. **Infra** — `Tests/XisfLib.Core.Tests.csproj` (xUnit, net8.0, ProjectReference `..\XisfLib.Core.csproj`);
    root csproj gets `<Compile Remove="Tests/**" />` + `<None Remove="Tests/**" />` and
    `VersionPrefix` 1.2 → 1.3; `publish.yml` gets a `dotnet test Tests/ -c Release` step before Pack;
    README drops the 128-bit float claim.

## Scope (out) — do not touch

## Test harness contract (Wave 1 shared surface)

One static helper class `Tests/TestKit.cs` owned by the wave-1 infra agent; other test authors code
against these signatures:

- `Task<XisfUnit> RoundTrip(XisfUnit unit, XisfWriterOptions? w = null, XisfReaderOptions? r = null)`
  — write to MemoryStream, read back.
- `Task<XisfUnit> ReadBytes(byte[] file, XisfReaderOptions? r = null)` — read a crafted file.
- `byte[] BuildMonolithic(string headerXml, params byte[][] attachedBlocks)` — assembles signature +
  headerLength(uint32 LE) + 4 reserved zero bytes + header + padding + blocks at stated positions;
  caller writes `attachment:pos:size` values consistent with the layout it requests; helper exposes
  the chosen positions.
- `XisfImage Gray8(int w, int h, byte fill)` / `XisfImage GrayF32(int w, int h, float fill)` — minimal
  valid images for write tests.

Fixtures: synthesized golden bytes only (built in-test or as small checked-in files under
`Tests/Fixtures/`); never copy user image libraries into the repo. Legacy-compat fixtures are
hand-crafted headers imitating v1.2 output (bare names, no checksums) and N.I.N.A.-style headers
(hyphenated sha names) — small and synthetic.

## Wave rules

- **Wave 1 (test authoring)**: write test sources + fixtures + `TestKit.cs` + test csproj. NO dotnet
  build/test/restore runs at all. Where current behavior is correct (zstd round-trip, checksum-over-
  stored-bytes), tests document it and are expected green in wave 2; each test file carries a header
  comment block listing EXPECTED-RED test names (with the gap they pin) vs EXPECTED-GREEN.
- **Wave 2 (scaffold + red/green ledger)**: add the minimal library stubs so everything COMPILES
  (new records/exception/properties from this contract; stub bodies may throw
  NotImplementedException), apply the csproj/`publish.yml`/README infra items, then run
  `dotnet build` + `dotnet test` and write `Journal/20260919.rev1-red-green-ledger.md`: every test
  → red/green vs its declared expectation; investigate and resolve every mismatch (fix the TEST only
  when the test contradicts spec or contract — record each such fix). No production logic beyond
  stubs.
- **Wave 3 (fail→pass)**: implement the contract until the full suite is green; zero warnings; no
  test may be weakened to pass (any test change needs a contract-cited justification in the ledger);
  finish by updating the day's journal entry.

## Amendment 1 (post-wave-1, binding on waves 2+3)

Consolidates the flags from all three wave-1 reports; where this conflicts with the sections above,
the amendment wins.

**Scope additions (spec conflicts surfaced by tests):**
- A1. String property serialization: emit as element CHARACTER DATA, never a `value` attribute
  (§11.1.6 forbids it; attribute-value normalization destroys embedded newlines — breaks
  `AstrometricSolution:...:Terms`). Reader must NOT trim String character content (whitespace is
  significant) but must keep accepting legacy `value`-attribute Strings (our v1.2 output).
- A2. `PropertyIdRegex` in Validation.cs: `::` → single `:` per corrected §8.4.1, and wire
  `ValidateImage` into `ValidateUnit` (dead code today); both are prerequisites of item 13.
- A3. Compression attribute emit: NO third component for non-`+sh` codecs (§10.6 gives two components
  for zlib/lz4/lz4hc/zstd; today the itemSize is emitted unconditionally). Emitted-bytes change —
  journal line required.
- A4. Writer honors a caller-supplied `XisfCompression` record on a data block (codec/itemSize/
  subblocks) when present; `Options.DefaultCompression` applies only when the block carries none.
- A5. Unsupported codec / checksum algorithm must NOT throw during header/metadata deserialization
  (`ParseCompression` currently throws `FormatException` there); the typed
  `XisfUnsupportedObjectException` surfaces only when the affected block is materialized
  (`ReadAsync`); `ReadMetadataFromStream` succeeds regardless. No new public read API.

**Naming decisions (already assumed by wave-1 tests — do not rename):**
- A6. `XisfRawProperty(string Id, XElement Element)`.
- A7. `XisfMetadata` new fields: `BlockAlignmentSize` (ushort?), `ChecksumAlgorithms` (string?),
  `MaxInlineBlockSize` (ushort?), `OutputHints` (string?) — add as named/optional; tests pass them by
  name, positional order is free.
- A8. Vector/matrix/scalar type identifiers: EMIT the spec's primary name (`UI8Vector`, `I32Vector`,
  `F64Matrix`, `Int32`, …); ACCEPT both primary and alternate (`ByteArray`, `Vector`, `IMatrix`,
  `Int`, `Float`, …) on read.
- A9. Validation stays `internal`; tests reach it via `XisfWriter.Validate` — do not add
  `InternalsVisibleTo`.

**Implementation hazards (wave 3 must handle; wave-1 reports carry the anchors):**
- A10. Shuffle exactly once: `CompressionProvider.CompressAsync` shuffles internally AND
  `DataBlockProcessor.WriteDataBlockAsync` shuffles again — pick a single owner (provider
  recommended) and make subblock handling preserve the invariant shuffle-whole → split → compress
  each / decompress each → concat → unshuffle-once.
- A11. Read→write currently drops `Compression`/`Checksum` when `MonolithicStorageStrategy` re-wraps
  attached pixels as `InlineDataBlock`, and `ExtractPixelDataAsync` throws on `AttachedDataBlock` —
  the item-9 write restructure must fix the drop without reintroducing the throw.
- A12. Unknown-root-element handling: remove the uid-gated `XisfReference("")` mangling and its
  compensating write-side skip TOGETHER, or preservation double-emits.
- A13. Block-backed property values need plumbing from the storage strategy (the deserializer sees a
  detached `XElement` today) — new internal pathway, not just a new switch case.
- A14. `XisfReaderOptions.FileStreamProvider`/`UriStreamProvider` are ignored by
  `ComponentFactory.cs:50` — known dead; out of scope, do not fix incidentally.

**Harness facts:** `TestKit.BlockBase = 4096` (first attached block at 4096, later blocks contiguous,
header space-padded); `NamespaceTests.HeaderProbe` is a second, independent helper that derives
positions empirically and assumes blocks are appended contiguously at EOF with no trailing padding.
