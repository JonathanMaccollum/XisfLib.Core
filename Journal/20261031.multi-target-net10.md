# 2026-10-31 — Multi-target net8.0 and net10.0

From `../EigenFrame.Docs/ArchitectureReview.20261031.md` §2 concern 11 (net8.0 support ends 2026-11-10) and §5.8; desk decision: multi-target so net10 consumers get a net10 build and any outside net8 consumer keeps working.

- `XisfLib.Core.csproj` and `Tests/XisfLib.Core.Tests.csproj`: `TargetFramework net8.0` became `TargetFrameworks net8.0;net10.0`. The test project runs the suite against both builds. Version untouched; the publish flow owns it.
- `.github/workflows/publish.yml`: `setup-dotnet` now installs 8.0.x and 10.0.x. Needed: the net10.0 target cannot build on the 8 SDK, and the net8.0 test leg needs the 8 runtime. A local pack confirmed the package carries `lib/net8.0` and `lib/net10.0`.

Results before the short-read fix below: Release build 0 errors, 8 CA2022 warnings on net10.0; tests 480 passed, 2 skipped, on each of net8.0 and net10.0.

## Short-read fix (desk decision, same day)

The net10.0 analyzer flagged 8 CA2022 sites where a `ReadAsync` result was ignored, so a short or truncated read left the buffer partly zero-filled and returned it as data. That breaks the 1.4 principle: malformed data throws rather than silently truncating. Each site now uses `ReadExactlyAsync` and throws `EndOfStreamException`. That is the shape the attached-block readers already use (`ReadExactly` and the explicit loop in `DataBlockProcessor.cs`), and the one `Storage.cs` uses for the monolithic header, so no `InvalidDataException` wrapping was added. Sites: `StreamResolver.cs` (XISB file header, block-index node header and elements, block read), `XisfReader.cs` (`ReadHeaderAsync` file and XML header, storage-format signature sniff), `DataBlockProcessor.cs` (positioned external block read). Nothing was suppressed.

Test: `Tests/DataBlockLocationTests.cs` `Read_TruncatedAttachmentBlock_Throws` cuts 10 bytes off a monolithic file's attached block and asserts `EndOfStreamException`. It goes through the public reader, so it guards the monolithic attached path, which already threw. None of the 8 changed sites can be reached cheaply through the public API: the serializer never sets `ExternalDataBlock` position or size, nothing calls `OpenDataBlocksFileAsync`, and `ReadHeaderAsync` needs a file on disk, which has no existing fixture.

Results: Release build 0 warnings and 0 errors on net8.0 and net10.0 (library and tests). Tests: 481 passed, 2 skipped, on each framework. EigenFrame.Desktop tests through the local flip: 212/212.
