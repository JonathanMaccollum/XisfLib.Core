# XISF 1.0 Revision 1 — conformance assessment (no code changes)

Assessment only. Sources: `XisfLib\docs\XisfSpecification 1.0 Revision 1.md` (+ announcement) and the
current `XisfLib.Core` source (v1.2.x, net8.0). Two recon passes: a full spec-delta digest and a
file:line implementation audit; this entry is the cross-reference.

**Caveat that gates future implementation work:** the markdown copy of the Revision 1 spec has all
mathematical formulas and figures stripped (Eqs [1]–[64] appear only as reference markers). Every
prose rule, identifier, regex, grammar, and table survived and is what this assessment uses — but the
Annex B color math, display-function equations, Wendland C² weight, RBF kernels, and Annex A
projection formulas are NOT in that file. Any implementation touching those must work from the HTML
spec at https://pixinsight.com/doc/docs/XISF-1.0-spec/XISF-1.0-spec.html.

## Verdict

XisfLib.Core **cannot currently claim Revision 1 conformance**, but the largest Rev-1 headline item is
already covered: **zstd and zstd+sh are fully wired for read and write** (`Compression.cs:16-26`,
ZstdSharp.Port 0.8.8 — Zstandard frame format, matching §10.6.9), and checksum verification of
SHA-1/256/512 over the stored (compressed) bytes is correct (`DataBlockProcessor.cs:57-65`). What
blocks conformance is mostly **pre-existing base-spec gaps that Revision 1 promoted from "implicit"
to explicit MUSTs** — plus one Rev-1-new decoder MUST (Boolean `0`/`1`).

## A. Rev 1 decoder baseline (§7.2) scorecard

| # | Baseline requirement | Status |
|---|---|---|
| 1 | Read monolithic files | ✅ |
| 2 | Read properties of ALL 8/16/32/64-bit scalar types | ❌ only Int32/UInt32/Float32/Float64 (+Boolean/String/TimePoint); every other width silently misparses as String (`XmlSerializer.cs:294-296`) |
| 3 | Read multiple Image elements | ✅ |
| 4 | Read inline, embedded AND attachment locations | ❌ inline and `location="embedded"` blocks deserialize as **empty data, silently** (`XmlSerializer.cs:345-353`); only attachment/url work. The `<Data>` child path at `XmlSerializer.cs:153-166` is only reached when no `location` attribute exists, which spec-correct embedded blocks always have |
| 5 | Read data blocks in BOTH byte orders | ❌ `byteOrder` attribute is never parsed anywhere; `ConvertByteOrder` (`DataBlockProcessor.cs:195-228`) is dead code — big-endian files silently mis-decode as LE |
| 6 | Decompress all standard codecs incl. zstd/zstd+sh | ✅ codecs; ❌ **compression subblocks** (`subblocks` attribute) are modeled (`Models.cs:73`) and half-built (`Compression.cs:267-288`) but never parsed/emitted/wired — a subblocked file today would decompress wrong or fail |
| 7 | Verify SHA-1/256/512 checksums | ✅ (default-on, over stored bytes — correct per §10.5). Nit: sha3-* parse fine but throw `NotSupportedException` at verify time; Rev 1's unsupported-object rule says treat the block unavailable, keep the unit accessible |
| 8 | Planar and normal storage models | ⚠️ tag pass-through only; acceptable for a byte-level library, but §8.5.3 now normatively fixes both orders (channel-consecutive planar, channel-interleaved normal) — should be documented as the contract callers rely on |
| 9–10 | UInt8/UInt16/Float32, Gray+RGB | ✅ |

Also decoder-side, Rev-1 MUSTs outside the numbered list:

- **Boolean `1`/`0` must be accepted** (§8.3.4). `bool.Parse` at `XmlSerializer.cs:269` throws on them. New hard requirement.
- **Non-finite floats:** grammar is `NaN | [-+]Inf | -?nan | -?inf`, decoders must accept all. .NET invariant `double.Parse` accepts none of `+Inf`/`-Inf`/`inf`/`nan` (it wants `Infinity`). Read FAIL — and on **write** we emit `Infinity`/`-Infinity`, which is not in the spec grammar at all. Both directions non-conformant today.
- **Unsupported object ⇒ object unavailable, rest of unit accessible** (§7). Our failure mode for unsupported codec/checksum/format is generally an exception that kills the whole read. Needs a policy pass.
- **Unrecognized elements/attributes ⇒ ignore**: we mostly do (silently drop), which satisfies the decoder rule — but see the preservation obligations in §C below, which dropping violates for read-modify-write.

## B. Rev 1 encoder baseline (§7.1) scorecard

Mostly fine: monolithic ✅, Metadata mandatory props ✅ (`XmlSerializer.cs:418-426`), attachment ✅,
planar ✅, UInt16 ✅, Gray/RGB ✅. Two failures:

- **Write properties of all 8/16/32/64-bit scalar types** — `SerializeProperty` throws
  `NotSupportedException` for Int8/UInt8/Int16/UInt16/Int64/UInt64 (`XmlSerializer.cs:496`). Baseline FAIL.
- **XML namespace**: the writer never declares `xmlns="http://www.pixinsight.com/xisf"` and emits all
  elements in no-namespace, while declaring an `xsi:schemaLocation` (`XmlSerializer.cs:385-390`).
  With Rev 1 shipping a formal XSD, every file we write fails schema validation. Our own reader
  tolerates both forms, so this is an interop defect, not a self-round-trip one.

Non-baseline but broken write paths worth recording:

- **Checksums are never emitted**, regardless of `CalculateChecksums`/`ChecksumAlgorithm` options —
  the monolithic writer leaves `Checksum` null (`XisfWriter.cs:198,244`) and the one code path that
  computes a digest discards it (`DataBlockProcessor.cs:126-128`). The options are dead knobs.
- `+sh` codec with no `ItemSize` silently skips shuffling → the emitted attribute lies about the
  encoding. Needs validation.
- Byte-shuffle tail rule (§10.6.2: bytes not forming a complete item stay unshuffled, stored after the
  shuffled run) — verify `Compression.cs:195-251` against this; the audit did not confirm tail handling.
- Distributed storage (`.xish`/`.xisb`) writes header-only, no data-blocks file
  (`XisfWriter.cs:347-349`, `StreamResolver.cs:458-468` throws). Either finish or stop exposing it.

## C. AstrometricSolution namespace (§11.5.3.7) — the headline feature

XisfLib.Core has **zero** astrometry support today, and that is *almost* fine: the namespace is plain
XISF properties (String/Int32/Float64/Boolean scalars + F64Vector/F64Matrix/I32Vector). The library's
job is to carry them faithfully. Two real obligations land on us:

1. **Prerequisite: Vector/Matrix property support.** Solutions are stored as `F64Vector`/`F64Matrix`
   (+ one `I32Vector`), typically as attached data blocks with zstd+sh (the spec recommends exactly
   that). Today: vectors/matrices can neither be written (throws) nor read (misparsed as String), and
   `<Property>` elements with a `location` attribute (block-backed property values) are not handled at
   all (`XmlSerializer.cs:249-298` never looks at `location`). **This is the single biggest work item
   Rev 1 implies for us** — without it, EigenFrame cannot read PixInsight 1.9.5 solutions or write its
   own (directly relevant to the sky-absolute campaign, `EigenFrame.Docs/CatalogPlateSolveSyntheticReference.md`).
2. **Preservation semantics.** Encoders shall preserve all solution properties they don't modify —
   including unrecognized ones — when geometry is unchanged, and a decoder not supporting the
   solution's major revision shall preserve everything untouched on write. Our current pipeline drops
   unrecognized properties/elements, which makes any read-modify-write flow non-conformant the moment
   a solution is present. (The matching destructive rule — remove the whole namespace on any geometric
   transform other than translation/uniform-scale/90°-rotation/mirror — is a *host* responsibility,
   e.g. EigenFrame, but the library must make preservation possible.)

Evaluating solutions (projections, RBF splines, Wendland weights) is out of scope for XisfLib.Core —
that math belongs host-side (or in EigenFrame.PreProcessing) and needs the HTML spec's equations.
The library's Rev-1 duty is carriage + preservation, not evaluation.

## D. Other Rev-1 items mapped to the code

- **Four new metadata properties** (`XISF:BlockAlignmentSize` UInt16, `XISF:ChecksumAlgorithms`,
  `XISF:MaxInlineBlockSize` UInt16, `XISF:OutputHints`): easy adds — but note `SerializeMetadata`
  currently drops 15 of the 19 *already-modeled* metadata fields (`XmlSerializer.cs:413-446`), so the
  metadata surface needs a general completion pass, not just four new names.
- **Image `id` uniqueness** is now a MUST — `Validation.cs` doesn't check it; cheap to add.
- **Empty vectors/matrices** = zero-length inline blocks (the one legal zero-length block). Falls out
  of the vector/matrix work; note any `length > 0` assertions must except this case.
- **UUIDs**: `Guid.NewGuid()` (v4, OS entropy) satisfies the relaxed Rev-1 rule (high statistical
  quality; xoshiro256** merely recommended). No change needed. Block-index ids only matter if
  distributed storage is ever finished.
- **sha3-256/sha3-512** stay optional; Rev 1 pins them to FIPS 202 (not original Keccak). If we ever
  enable them, .NET 8's `SHA3_256`/`SHA3_512` are FIPS 202 — correct — but are OS-gated
  (`IsSupported`); keep optional.
- **Checksum-fail on compressed block ⇒ must NOT decompress** (§10.5 security rule): we verify before
  decompressing (`DataBlockProcessor.cs:57-77`) — already conformant; keep that ordering pinned.
- **`compression` attribute placement for embedded blocks** goes on the child `<Data>` element, not
  the parent — moot until embedded read/write works, but record it for that fix.
- **URL/path parentheses correction** (location extends to the LAST `)`): check
  `DeserializeDataBlockLocation` (`XmlSerializer.cs:343-377`) uses last-paren semantics when parsing
  `url(...)`. `path(...)` is not parsed at all today (StreamResolver's `@header_dir` logic is dead
  code) — a smaller baseline-adjacent gap (path is not in the decoder baseline; low priority).
- **Property format specifiers** (§8.4.3, several corrections): our entire `XisfPropertyFormat` is
  inert plumbing — we neither apply nor emit formats. Claiming *no* support is a legal position under
  Rev 1 (it binds "implementations declaring support"); either implement per the corrected rules or
  document non-support. Don't half-claim.
- **Color space math (Annex B, now normative)**: the library carries `colorSpace` as a tag and does no
  conversion — that keeps us out of Annex B's blast radius, including the *corrected* CIE L*a*b*
  normalization (a behavioral change for anyone who implemented the original equations). If a consumer
  ever asks the library to interpret CIELab pixels, the math must come from the HTML spec, Rev-1 form.
- **RGBWorkingSpace / ICCProfile / DisplayFunction / Thumbnail**: modeled but with zero
  (de)serialization, and unrecognized root elements are dropped (data loss on round-trip). Rev 1
  tightens RGBWS (`Y` must be derived from chromaticities + D50; `gamma` may be the word `sRGB`) and
  makes DisplayFunction/orientation obligations bind anyone claiming support. Current honest position:
  we support none of these; the defect is that we *destroy* them on round-trip instead of preserving.
- **`orientation`** attribute: enum exists, never parsed or written (`XmlSerializer.cs:241`). Same
  round-trip-loss class.
- **Non-namespace README claim**: README says 128-bit float support; `XisfSampleFormat` has none.
  128-bit is optional under Rev 1 — fix the README, not the code.

## E. Backward compatibility and versioning for consumers

Consumers: EigenFrame.Desktop + XisfPrep float `1.*`; EigenFrame.Worker pins 1.1.3.

- **Almost everything above is additive or a bugfix** (accepting Boolean 0/1, new property types, new
  metadata, byteOrder wiring, inline/embedded read, checksum emission behind existing options):
  suitable for 1.x minors under the current auto-publish scheme.
- **Two changes alter emitted bytes** and deserve a deliberate, called-out release (bump
  `VersionPrefix`, journal the delta, verify against PixInsight/N.I.N.A. before shipping): (1) putting
  all elements in the XISF namespace, (2) emitting checksums by default if the default changes.
  Neither changes the .NET API surface, so consumers' code compiles unchanged; the risk is third-party
  *readers* of our files, and the namespace change strictly improves conformance.
- **Writing zstd by default** would break pre-Rev-1 third-party decoders (the announcement's one
  acknowledged break). Keep the write-side default at zlib/lz4 and let callers opt into zstd;
  EigenFrame internals (Worker/Desktop, both on this library) can adopt zstd+sh freely since we read it.
- Spec-digest flagged unadvertised edges to keep in mind when hardening the reader: zero-length inline
  blocks, raw parentheses in url/path, lowercase `nan`/`inf` forms — all things Rev-1 files may
  legally contain that strict pre-Rev-1 readers choke on.

## F. Version + test strategy proposal (agreed direction, pre-implementation)

**Version: bump `VersionPrefix` to 1.3** in the same change set as the implementation, so the first
auto-published build of the new behavior is 1.3.x. Minor, not major: the .NET API stays
compile-compatible (work is wiring already-modeled records + honoring dead options); minor, not a
silent 1.2.x patch: emitted bytes change (XISF namespace, checksum attributes) and read behavior
changes (byteOrder, inline/embedded, typed scalar widths). Write-side codec default stays zlib/lz4 —
zstd is opt-in (PixInsight 1.9.1, the manual-verification target, predates zstd). Escape hatch: if
PI 1.9.1 rejects namespace-qualified headers (unlikely), gate the namespace behind a writer option.
Consumers: Desktop/XisfPrep float `1.*` and pick 1.3 up automatically; Worker's 1.1.3 pin insulates
the ungated cloud path until deliberately bumped; EigenFrame changes depending on 1.3 behavior use an
explicit floor `[1.3.0,2.0)`; release verification with `-p:UseLocalXisfLib=false`.

**Tests: new `XisfLib.Core.Tests` project (xUnit, net8.0, ProjectReference), with a `dotnet test`
step added to `publish.yml` before pack** — since every push to main publishes, tests become the
release gate. Focused instruments, not a comprehensive suite:
1. In-memory round-trip harness (writer→MemoryStream→reader): property matrix (all scalar widths;
   Boolean true/false emit + 1/0 accept; all six non-finite tokens parse, canonical-only emit;
   vectors/matrices incl. empty zero-length inline and block-backed zstd+sh), compression×shuffle
   matrix (every codec × item sizes 2/4/8 × non-multiple block length for the shuffle-tail rule),
   checksum emission per options.
2. Golden-byte fixtures for reader-only paths: big-endian blocks (programmatic byte-swap),
   inline/embedded blocks, subblocked compression (crafted so wrong shuffle-before-split ordering
   corrupts), sha3 checksum declaration ⇒ block-unavailable not unit-fatal, an AstrometricSolution
   property set (real PI 1.9.5 file when available; spec worked-example values until then).
3. Preservation + partial-failure: unknown elements/properties survive read→write untouched;
   unsupported codec/format ⇒ that object unavailable, rest of unit readable.
4. Legacy-compat regression fixtures (highest weight): real N.I.N.A. + PixInsight 1.9.1 files AND our
   own v1.2 output (no namespace, no checksums) — the reader must accept both header forms forever.

Manual PI 1.9.1 pass covers the rest: 1.3-written files (namespace + checksums + zlib/lz4) open for
normal processing; AstrometricSolution properties appear as inert unknowns; one deliberate zstd file
to confirm the graceful-failure mode rather than assume it.

**Repo layout for tests:** no restructure. Follow the `EigenFrame.PreProcessing` precedent — library
csproj stays at repo root, tests in `Tests/XisfLib.Core.Tests.csproj`. Keeps `publish.yml`'s root
grep/build/pack and the workspace `UseLocalXisfLib` ProjectReference paths untouched. One C#-specific
addition required (F# precedent didn't need it): the root csproj must `<Compile Remove="Tests/**" />`
+ `<None Remove="Tests/**" />` so implicit globs don't pull test sources into the library. No `.sln`
(PreProcessing has none); CI targets `Tests/` explicitly.

**Implementation kicked off 2026-09-19** as a three-wave TDD fan-out (tests authored → scaffold
compiles with expected reds → fail→pass implementation); shared API decisions frozen in
`Journal/20260919.rev1-implementation-contract.md`. All changes confined to this repo; nothing
committed by agents.

## G. Suggested priority order (when implementation is authorized)

1. **Decoder baseline blockers**: inline/embedded block content; byteOrder parse + conversion wiring;
   all scalar widths read/write; Boolean 0/1 + non-finite float token forms (both directions).
2. **Vector/Matrix/block-backed properties** — unlocks AstrometricSolution carriage and empty-vector
   semantics; adopt zstd+sh for these blocks per spec recommendation.
3. **Preservation**: stop dropping unrecognized elements/properties; opaque pass-through for unknown
   core/extension elements and unknown namespaced properties (AstrometricSolution preservation falls
   out of this).
4. **Writer conformance**: XISF namespace on emitted elements; actually emit checksums per options;
   `+sh` ItemSize validation; shuffle-tail verification; Image `id` uniqueness validation; four new
   metadata properties + finish `SerializeMetadata`.
5. **Compression subblocks** (parse + emit + shuffle-before-split ordering per §10.6): needed for
   >4 GiB zlib blocks and to read files from encoders that use them for parallelism.
6. Decide-and-document: format specifiers (support or declare non-support), distributed storage
   (finish or remove), sha3 enablement, README 128-bit claim.

**Implementation completed 2026-09-19.** Wave 3 took the suite from 124/284 to **284/284 passing**,
library and test project both building with zero warnings; no test was weakened. Contract items
1–14 are implemented (item 14 was verify-only and needed no change; item 15 landed in wave 2).
Detail, per-area deviations and the emitted-bytes delta are in
`20260919.rev1-red-green-ledger.md` ("Wave 3 outcome"); the binding decisions are in
`20260919.rev1-implementation-contract.md`.

Files changed in the library: `XmlSerializer.cs` (rewritten — namespace emission, the full scalar/
vector/matrix type tables of §8.4.4, non-finite and Boolean grammars, String character data,
inline/embedded/`url(...)` block parsing, subblocks, `byteOrder`, unknown-content preservation, the
complete Metadata surface), `DataBlockProcessor.cs` (verify → decompress → unshuffle → convert
ordering, subblock decompression, the single shuffle owner, a synchronous read path),
`Compression.cs` (codec-only), `Storage.cs` (materializes inline and embedded pixel data, threads
the block reader), `XisfWriter.cs` (stored bytes → digest → header), `Validation.cs` (single-colon
property identifiers, `ValidateImage` wired in, image-id uniqueness, `+sh` item size),
`Models.cs` and `Interfaces.cs` (the carrier for unsupported declarations and the block-reader seam).

§G's priority list is discharged except for item 6's open decisions: format specifiers are now
documented as unsupported (wave 2's README note), sha3 stays optional and now fails as an
unsupported *object* rather than killing the read, and distributed `.xish`/`.xisb` writing is still
header-only — unchanged and still owed a finish-or-remove decision.
